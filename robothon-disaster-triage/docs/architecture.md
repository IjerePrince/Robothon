## 2. MJCF Scene Composition

The main scene (`models/scene.xml`) is **monolithic** by design —
MuJoCo's `<include>` directive merges files but does not cleanly handle
multiple top-level `<default>` and `<asset>` blocks.  To keep the
project maintainable while avoiding include pitfalls:

- `models/scene.xml` — the ONE file you load.  Contains:
  - `<compiler>`, `<option>`, `<visual>`, `<default>`, `<asset>`
  - Inline floor, lights, cameras, table
  - Inline UR5e kinematic chain (6-DOF)
  - Inline Shadow Hand Lite kinematic chain (16-DOF, welded to UR5e flange)
  - Inline disaster objects + bins + container with hinged lid
  - Inline `<actuator>`, `<sensor>`, `<equality>` blocks
- `models/shadow_hand_lite.xml` — generated by
  `scripts/build_shadow_hand.py` for STANDALONE testing of the hand
  (loads without the UR5e/table).  Useful for debugging finger kinematics.
- `models/ur5e.xml` — UR5e fragment, kept for reference.  The same
  kinematic chain is inlined in scene.xml.
- `models/disaster_objects.xml` — disaster objects fragment, kept for
  reference.  The same object set is inlined in scene.xml.
- `models/include/assets.xml` — shared materials + default classes,
  used by the standalone model files (NOT included by scene.xml).

## 3. Sensor Layout

The scene defines 41 sensors, totalling 56 data values:

| Group                     | Count | Dim each | Total | Purpose                              |
|---------------------------|-------|----------|-------|--------------------------------------|
| `<touch>` tactile         | 6     | 1        | 6     | Fingertip + palm contact forces (N)  |
| `<jointpos>` UR5e         | 6     | 1        | 6     | UR5e joint angles (rad)              |
| `<jointvel>` UR5e         | 6     | 1        | 6     | UR5e joint velocities (rad/s)        |
| `<jointpos>` Shadow Hand  | 16    | 1        | 16    | Hand joint angles (rad)              |
| `<framepos>` objects      | 5     | 3        | 15    | Object xyz positions (m)             |
| `<framepos>` palm         | 1     | 3        | 3     | Palm xyz position (m)                |
| `<framequat>` palm        | 1     | 4        | 4     | Palm orientation quaternion          |

The `<touch>` sensor is MuJoCo's built-in tactile model: it integrates
the normal force at the site over the contact patch, producing a single
scalar (N) per sensor.  Saturation is at 50 N (configured in env.py).

## 4. Equality Constraints

Two equality constraints demonstrate different MJCF constraint types:

### `eq_lid_pivot` — `<connect>` (3-DOF point constraint)
```xml
<connect name="eq_lid_pivot" active="true"
         body1="container_base" body2="container_lid"
         anchor="0.40 0.060 0.760" />
```
The lid is constrained to maintain a fixed 3-DOF point at the back edge
of the container base.  Combined with the lid's hinge joint (`lid_hinge`,
range -0.05 to 1.57 rad), this creates a working hinge mechanism — the
lid can swing open from 0° to 90°.

### `eq_hand_to_glass` — `<weld>` (6-DOF rigid attachment)
```xml
<weld name="eq_hand_to_glass" active="false"
      body1="palm" body2="obj_glass"
      relpose="0 0 0 1 0 0 0" />
```
This weld is defined but **not active** by default.  When activated at
runtime (future work), it rigidly attaches the glass vial to the palm —
simulating a "magnetic grasp" without relying on friction alone.  This
demonstrates how the project uses MuJoCo's equality constraint system
for runtime-actuated mechanical couplings.

## 5. Robot Kinematics

### UR5e (6-DOF)
Standard UR5e kinematic chain, all joints limited to factory ranges
(±6.28 rad except elbow ±3.14 rad):

```
base_link (fixed to world at z=0.781)
  └─ shoulder_link  [shoulder_pan_joint,    z-axis, ±6.28 rad]
      └─ upper_arm_link [shoulder_lift_joint, y-axis, ±6.28 rad]
          └─ forearm_link [elbow_joint,       y-axis, ±3.14 rad]
              └─ wrist_1_link [wrist_1_joint, x-axis, ±6.28 rad]
                  └─ wrist_2_link [wrist_2_joint, y-axis, ±6.28 rad]
                      └─ wrist_3_link [wrist_3_joint, x-axis, ±6.28 rad]
                          └─ palm (welded, no joint)
```

Each UR5e joint uses a `<position>` actuator with kp=200, damping=5.0,
armature=0.1, frictionloss=0.05, forcerange=[-150, 150] Nm.

### Shadow Hand Lite (16-DOF)

Built from primitives (capsules for phalanges, spheres for knuckles).
Per-finger DOF breakdown:

| Finger | Joints          | DOF | Total length (mm) |
|--------|-----------------|-----|-------------------|
| Thumb  | CMC ab/ad, CMC flex, MCP flex, IP flex | 4 | 136 |
| Index  | MCP ab/ad, MCP flex, PIP flex         | 3 | 103 |
| Middle | MCP ab/ad, MCP flex, PIP flex         | 3 | 106 |
| Ring   | MCP ab/ad, MCP flex, PIP flex         | 3 | 96  |
| Little | MCP ab/ad, MCP flex, PIP flex         | 3 | 86  |
| **Total** |                                  | **16** | |

Each hand joint uses `<position>` with kp=40, damping=0.3, armature=0.005,
forcerange=[-3, 3] Nm.

The thumb has an `euler="0 30 35"` base orientation (degrees) so it
opposes the other four fingers — critical for pinch grasps.

## 6. Reward Function

The per-step reward decomposes as:

```
r(s, a) = α * (
    + 0.5 * approach_bonus(palm, target)
    + 0.1 * contact_count(fingertips)
    + 2.0 * grasp_detected(one-time)
    + 0.2 * force_match(total_force, class_target)
    + 5.0 * placement_in_correct_bin(one-time)
    +10.0 * all_objects_placed(one-time)
    - 0.001 * ||action||_2
    - 0.01  * 1   # per-step time cost
    - 5.0   * fragile_break(one-time)
) where α = reward_scale (default 1.0)
```

**Failure conditions** (episode terminates as `failed=True`):
- A fragile object is subjected to >8N of total fingertip force for
  >10 consecutive steps.

**Success condition** (episode terminates as `success=True`):
- All 5 objects are placed in their correct triage bins.

**Timeout**: 1500 steps (30 seconds of simulated time at 20ms env dt).

## 7. Control Modes Compared

| Property                 | Scripted Controller            | PPO Policy                       |
|--------------------------|--------------------------------|----------------------------------|
| Source                   | `src/scripted_controller.py`   | `src/rl_train.py` + checkpoints  |
| Type                     | 10-state FSM + heuristic IK    | Neural network (256×256 MLP)     |
| Observation used         | palm_pose + object_poses + tactile | Flattened 78-dim obs         |
| Tactile ID method        | Nearest-template (mean, var)   | Implicit (learned)               |
| Grasp force control      | Per-class target profiles      | Implicit (learned)               |
| Bin placement            | Waypoint motion planning       | Implicit (learned)               |
| Episode length           | ~600-1500 steps                | ~200-1500 steps                  |
| Determinism              | Fully deterministic            | Stochastic (unless `deterministic=True`) |
| Best for                 | Demonstration, baseline        | Robust policy after training     |

## 8. Demo Video Composition

The demo MP4 is rendered by `src/demo_render.py` in 5 phases:

| Phase | Frames | Duration | Camera    | Content                                       |
|-------|--------|----------|-----------|-----------------------------------------------|
| 1     | ~225   | ~7.5s    | cycle     | Scene overview (front/side/top)               |
| 2     | ~600   | ~20s     | front/side| Scripted controller in action (FSM overlay)  |
| 3     | 60     | 2s       | top       | Top-down view of objects + bins               |
| 4     | 180    | 6s       | front     | Hand open/close cycle (16-DOF showcase)       |
| 5     | 120    | 4s       | front     | Project summary card                          |
| **Total** | ~1185 | ~40s   |           | (Extended to 60-90s with longer Phase 2)     |

Each frame is rendered via `mujoco.Renderer` (offscreen OpenGL under
Xvfb), annotated with OpenCV text overlays (title + subtitle bar), and
encoded to H.264 via imageio-ffmpeg.
